# 对账单 × 发货单 自动核对工具

销售跟客户对账时，手上是一张**对账单**和一叠**发货单**。以前靠人逐行加总，慢、易错、还说不清差在哪。

这个工具把「1 份对账单 + N 份发货单」核成**一个总额结论 + 一张可下载的明细表**：

- **结论只看总额**：对账单「应收增加」合计 ↔ 参与核对的所有发货单「发行实洋」合计，差一分就是不一致。
- **明细用来定位**：产品级列出双方金额与差额，方便查出是哪件货、哪张单出了问题。

实测（真实单据，1 份对账单 + 6 张订书单）：`40135.23 = 40135.23`，14 个产品全部一致。

- 载体：钉钉工作台 H5（手机 / 电脑都能开），单进程 Node 服务
- 输入：`.xlsx` / `.xls`
- 输出：页面总额卡片 + 明细 + `差异表-YYYYMMDD-HHmm.xlsx`

## 快速开始

```bash
npm install          # 首次
npm run samples      # 生成 9 个合成样例（可选，用于自测/演示）
npm start            # 默认 http://127.0.0.1:3000
```

打开 `http://127.0.0.1:3000`，先传 `samples/验收-对账单.xlsx` + `samples/验收-发货单-1.xlsx` + `samples/验收-发货单-2.xlsx`，可以看到总额不一致、明细里四类差异各一条。

想看「单据没有金额列」的情况，再传一次，把其中一张换成 `samples/无金额-发货单.xlsx`。

未配置钉钉凭据时自动进入**本地模式**（跳过免登）；配置后进入钉钉模式，详见 [docs/DEPLOY.md](docs/DEPLOY.md)。

## 口径（这一节是业务约定，改动要先确认）

| 项 | 取值 |
| --- | --- |
| 对账单金额 | **应收增加**（= 码洋 × 发行折扣，也就是入账的实洋） |
| 发货单金额 | **发行实洋** |
| 核对对象 | **总额**，不核数量、不核单价 |
| 误差 | 0；按「分」比较，`0.01` 就是不一致 |

> 订书单里还有「入账实洋」列（打过 60% 折扣的），**不能**拿来对：实测它比对账单少 1489.71。自动识别只认「应收增加 / 发行实洋」，绝不会把「标准金额 / 码洋」当实洋用。

## 它怎么算

### 1. 解析：自动找表头

真实表头**不在固定行**：对账单第 1 行，有的发货单第 3 行，有的第 10/11 行（前面是客户抬头、物流单号、联系人）。所以不写死行号，扫描前 60 行，按「同义词命中数」挑最像表头的一行。

识别结果在「确认映射」页摊开给用户改，每个 sheet 单独缓存。

**金额列只自动采用实洋列**：表头是「应收增加」或「发行实洋」才填；只有「标准金额 / 码洋 / 金额」的表留空，并提示用户手动指定。这是避免"以为在核实洋、其实比的是码洋"的唯一可靠做法。

### 2. 匹配：级联多字段（用于明细定位）

样例里三类表的可用键不一样：发货单 A 只有 ISBN，发货单 B 只有内部书号，对账单两列都有且编号体系不同。用「并查集」把两侧所有行连成产品实体：

1. **编码相等**（编码1 与 编码2 允许交叉）
2. **名称标准化后相等**（NFKC 全半角、去空格、破折号统一；出版社不相容时不连）
3. 剩下的单边实体做**名称相似度配对**（≥0.82），结果标 `fuzzy`，不静默
4. 仍未连上的 → 单边（仅对账单 / 仅发货单），并对单边之间给「疑似同一产品」提示

### 3. 金额：按「分」的整数比较

金额一律换算成 `BigInt` 分，`0.1 + 0.2 !== 0.3` 这类浮点误差进不了比较。真实对账单里 `应收增加` 是 `1125.94199999999` 这种浮点尾巴，解析时按 2 位小数接管。

### 4. 总额与明细

- 发货单总额 = **参与核对**的单据金额之和。没有金额列的单据不计入，也不按 0 计。
- 只要有单据没参与核对，就**不会**判「总额一致」——哪怕已参与部分刚好相等，结论也是「已参与核对的部分金额一致，另有 N 张单据未参与核对」。
- 明细分五类：`金额不一致` / `仅对账单有` / `仅发货单有` / `金额未知（单据无金额列）` / `一致`。金额未知的行显示「—」，不显示 0.00。

## 验收标准对照

| # | 验收标准 | 实现 | 验证 |
| --- | --- | --- | --- |
| 1 | 1 对账单 + ≥2 发货单，无需手工整理即可出结果 | 表头自动探测 + 字段自动识别 | `npm run e2e` 第 2 组 |
| 2 | **核对总金额**：对账单「应收增加」↔ 发货单「发行实洋」 | `summary.total` | e2e「总额按应收增加↔发行实洋计算」 |
| 3 | 差 0.01 判为不一致 | 分整数比较，零误差 | 单测「0.01 元差异必须能被区分」 |
| 4 | 不出现浮点假差异 | 全 BigInt | e2e「金额按分为整数比较」 |
| 5 | 明细可下载，含双方金额与差额 | 导出 8 列 | e2e「导出 8 列且不含数量列」 |
| 6 | 总额一致时显示「总额一致」且不生成空表 | `total.matched` → `NO_DIFF` | e2e「总额一致时不生成差异表」 |
| 7 | 单边产品单独归类 | `statement_only` / `shipment_only` | e2e「单边产品单独归类」 |
| 8 | 结果页显示参与汇总的发货单文件名与单据数量 | `summary.shipmentFiles` | e2e「参与核对的单据数与张数正确」 |
| 9 | 没有金额列的发货单不参与核对，且必须让人看见 | `amountChecked=false` + `excludedFileCount` | e2e 第 6 组 |

## 已知限制（都是有意为之，不是漏做）

- **要核金额，必须传带「发行实洋」的订书单**。`.xls` 老发货单只有「定价 + 数量」，没有实洋列，只能参与明细定位、不参与金额核对。想核金额就传订书单。
- **同一批发货的两份单据不要一起传**。真实样例里「天水卫校康养（文智达）7.24.xls」和「订书-兰州域航（天水卫校） 杨敏兰7.24.xlsx」是同一批货的两份单据（8 个产品数量完全相同），同时上传会让数量与金额都翻倍。工具无法判断归属，靠结果页的文件名 + 张数让人复核。
- **一次核对要传齐该对账单对应的全部发货单**。对账单是经销商维度、发货单按学校，漏传的学校产品会显示成「仅对账单有」，总额也会差。
- **合并单元格/两行表头**靠启发式（分组行+字段行拼接）；识别不准时在映射页手动指定表头行与列。
- **单表里重复的行会被跳过**：例如订书单里同一产品出现两行、第二行只有金额没有书号（小计/合并单元格常见），解析时按「缺产品名称/编码」跳过，不会重复累加。
- 单文件 20MB、发货单最多 30 张（环境变量可调）。
- 不做客户/区域数据隔离（需求假设：销售只核对本人上传的文件）。
- 读取 `.xls` 用的 `xlsx@0.18.5`（SheetJS 社区版）存在已知原型污染 CVE，官方修复版只在自有 CDN 发布。本项目只解析内网可信文件，风险可控。
- 核对结果只存内存（TTL 2 小时），服务重启即失效——本期不做历史归档。
